# ИИ-помощник поддержки

Умный ассистент службы поддержки на базе OpenAI-совместимого LLM API. Отвечает
клиентам по делу, знает базу знаний и профиль клиента, ведёт живой диалог,
экономит токены и передаёт сложные обращения живому оператору.

## Что умеет

- **Понимает контекст.** В каждый запрос подмешивается компактная сводка о
  клиенте (баланс, подписка, срок действия, трафик, устройства, реферальная
  история) и релевантные записи базы знаний.
- **Отвечает и на бытовые вопросы** («привет», «как дела», «спасибо») — коротко
  и по-человечески, затем мягко предлагает помощь.
- **Скользящая суммаризация.** Каждые `N` сообщений пользователя (по умолчанию 3)
  переписка сжимается отдельным запросом в короткое саммари, и дальше в контекст
  идёт именно оно — это резко снижает расход токенов на длинных диалогах.
- **Экономия токенов.** Ограничение истории, обрезка входящего текста, подбор
  только `top_k` записей базы знаний, дешёвая модель для суммаризации,
  лимит сообщений в сутки.
- **Передача оператору.** Если вопрос требует действий на стороне компании
  (проверка платежа, возврат, разблокировка, партнёрские условия) или клиент
  просит оператора — автоматически создаётся тикет и уведомляются админы.

## Как включить

1. Заполните переменные окружения (см. `.env.example`, блок «ИИ-АССИСТЕНТ
   ПОДДЕРЖКИ»):

   ```env
   AI_ASSISTANT_ENABLED=true
   AI_ASSISTANT_API_KEY=sk-...
   AI_ASSISTANT_BASE_URL=https://api.openai.com/v1
   AI_ASSISTANT_MODEL=gpt-4o-mini
   ```

   Работает с любым OpenAI-совместимым провайдером: OpenAI, DeepSeek, OpenRouter
   и т.п. — достаточно поменять `AI_ASSISTANT_BASE_URL` и `AI_ASSISTANT_MODEL`.

2. Примените миграции БД (`alembic upgrade head`) — создастся таблица
   `ai_conversations`.

3. В меню «Поддержка» появится кнопка «🤖 ИИ-помощник».

## Ключевые настройки экономии

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AI_ASSISTANT_SUMMARIZE_EVERY` | суммировать каждые N сообщений | 3 |
| `AI_ASSISTANT_HISTORY_LIMIT` | сколько последних реплик держать в контексте | 6 |
| `AI_ASSISTANT_KB_TOP_K` | сколько записей базы знаний подмешивать | 3 |
| `AI_ASSISTANT_MAX_INPUT_CHARS` | обрезка входящего сообщения | 1200 |
| `AI_ASSISTANT_MAX_TOKENS` | лимит токенов ответа | 500 |
| `AI_ASSISTANT_SUMMARY_MODEL` | (опц.) более дешёвая модель для саммари | — |
| `AI_ASSISTANT_DAILY_MESSAGE_LIMIT` | лимит сообщений на пользователя в сутки | 40 |

## База знаний

Хранится в `app/data/ai/knowledge_base.json` — компактный набор записей
(`topic`, `keywords`, `q`, `a`). При запросе выбираются наиболее релевантные
записи по ключевым словам и токенам, а не отправляется вся база — это
и точнее, и дешевле по токенам. Файл можно свободно редактировать и дополнять.

## Архитектура

- `app/services/ai/knowledge_base_service.py` — загрузка и retrieval по базе знаний.
- `app/services/ai/user_context.py` — сборка компактного профиля клиента.
- `app/services/ai/llm_client.py` — тонкий клиент OpenAI-совместимого API.
- `app/services/ai/ai_assistant_service.py` — ядро: контекст, вызов LLM,
  суммаризация, лимиты, передача оператору.
- `app/handlers/ai_support.py` — Telegram-хендлеры диалога.
- `app/database/models.py::AIConversation` — состояние диалога (саммари,
  последние реплики, счётчики, лимиты).
