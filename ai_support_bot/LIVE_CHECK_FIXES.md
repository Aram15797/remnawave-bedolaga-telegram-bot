# Исправления по реальному прогону поддержки

В присланном прогоне были три автоматических замечания и дополнительные проблемы, видимые при чтении ответов. Проверка в терминале также не покрывала отдельную ветку обработки сообщений Telegram.

| Проблема | Исправление |
|---|---|
| «А теперь покажи как в Telegram-боте» после подключения давало инструкцию оплаты Stars | Тема коротких и длинных уточнений восстанавливается по предыдущим вопросам пользователя. Известные действия получают точный раздел карты, без поиска по одному слову Telegram. |
| Покупка на сайте сопровождалась тарифами, инструкцией Telegram и отсутствием прямой ссылки покупки | Ответ по известному пути строится из карты интерфейса; используется только указанный канал и полный HTTPS-адрес. |
| Списки приложений сопровождались ненужным «Скачать подписку» | Для стандартных списков используется компактный ответ по выбранной платформе. |
| Техническая инструкция дублировалась целиком | Повторные копии ответа удаляются перед отправкой. |
| Все основные шаги диагностики выполнены, но бот продолжает советы | Явная неудача после выполненных действий требует передачи обращения по правилу в коде. |
| Запрос человека возвращал пустую строку | Обязательная передача обходится без модели; маркер без текста, пустой HTML и обрезанный ответ модели заменяются понятным уведомлением. |
| На возврат бот отвечал «не предусмотрен» и не передавал обращение | Явный запрос возврата обрабатывается обязательной передачей; старые тикеты и ответ модели не могут её отменить. |
| Незачисленный платёж на сайте ошибочно требовал привязать Telegram для ручной проверки | Привязка нужна для самостоятельного доступа к данным через бота. Для проверки командой достаточно собрать доступные сведения и передать обращение. |
| Пополнение без продления записывалось как незачисленный платёж, канал Telegram угадывался | Инструмент проверяет основание для такого сценария и наличие сообщённого канала покупки. |
| Запрос по неподтверждённому email сопровождался балансом и ссылками собственного Telegram-аккаунта | Чтение сразу ограничивается указанным email и текущим Telegram ID; подстановка другого аккаунта запрещена. Ограничение сохраняется для последующих вопросов без повторного email. |
| Все вопросы получали семь примеров из RAG и персональные данные | Известные пути, приложения и обязательные передачи не вызывают модель или RAG. Платёжный сбор сведений не использует старые тикеты. Общий текст остальных примеров ограничен 2400 символами. |
| После обновления код добавлял новую копию полного пакета правил к сохранённому старому | Сгенерированный стандартный пакет заменяется актуальным, без накопления нескольких версий. Пользовательский нестандартный промпт сохраняется. |
| Telegram-обработчик перехватывал «да» как болталку до чтения диалога | Короткие ответы проходят через общий обработчик контекста; простые приветствия и благодарности отвечаются локально в агенте. |
| Команда получала сведения об отправленном вложении без самого вложения | Telegram file ID сохраняется с обращением. При передаче отправляется вложение, только администраторам из настроек, с исключением автора. |
| История колеса подразумевала, что там можно увидеть сам код | Уточнено: история раскрывается нажатием «Последние вращения», а код показывается в результате выигрыша. Потерянный код требует ручной проверки. |

Ссылки и email других клиентов удаляются из примеров прошлых обращений перед передачей модели. Денежная сумма в ответе о стоимости должна подтверждаться актуальным каталогом, а не старым тикетом. Telegram HTML проверяется: разрешённые теги закрываются, текст экранируется, опасные адреса ссылок удаляются. Служебные сообщения администраторам также экранируют пользовательский текст.

Выбранная в рабочей админке модель не меняется. Клиент сохраняет причину окончания ответа и число reasoning tokens для диагностики; обрезанный по лимиту ответ не отправляется как полноценная инструкция. Формат параметров проверен по [официальной документации GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) и [документации reasoning-моделей](https://developers.openai.com/api/docs/guides/reasoning).

## Повторная проверка

После загрузки правок на сервер:

```bash
docker compose build ai_support_bot
docker compose up -d --no-deps --force-recreate ai_support_bot
docker compose exec -T ai_support_bot python -u -m ai_support_bot.check_support --telegram-id 925238030
```

Прогон теперь также отмечает пустые ответы, повторы, ответ об оплате вместо подключения, лишнюю инструкцию Telegram при запросе сайта и выдачу персональных данных в сценарии неподтверждённого email. Поле «источник» показывает, получен ли ответ по правилам или от модели. Нулевое количество замечаний не заменяет чтение смысла ответов.

Отдельно в Telegram проверьте диалог оплаты с ответом «да», загрузку реального чека и последующую передачу обращения: текстовый прогон не проверяет доставку Telegram и распознавание изображения. Автотесты используют подменённые ответы API и Telegram. В локальном окружении нет ключа API и рабочей БД, поэтому повторный живой прогон возможен на сервере.

## Второй живой прогон

Лог от 16.10.2026: 14 запросов к модели, 52 303 входных и 681 выходной токен. Подключение, выбор приложений, основные ссылки, передача оператору, возврат и сотрудничество отработали корректно. Автоматический результат «0 замечаний» пропустил три смысловые ошибки, исправленные после чтения ответов:

- Детерминированная навигация копировала внутренние подсказки «не обещай», «не предлагай». Публичные пояснения теперь хранятся отдельно от подсказок для модели. Убраны технические подробности о загрузке способов оплаты и повторяющийся префикс обзора разделов.
- После сообщения об отправленной выписке модель задавала сразу несколько вопросов. При активном незачисленном платеже ответ проверяется по сохранённым сведениям: только следующий неизвестный пункт, затем передача команде. Сохранение сведений и обновление данных аккаунта остаются динамическими.
- После вопроса о чужом email новая тема получала прежний ответ о приватности. Продолжение вопроса об аккаунте сохраняет ограничение по email; самостоятельная новая тема сбрасывает его. Запрос внутренних инструкций получает отдельный краткий отказ. Новая техническая проблема также завершает прежний сбор сведений о платеже.

Регрессионные проверки воспроизводят эти ответы. Живой сценарий теперь отмечает утечку внутренних указаний, лишние вопросы на первом шаге оплаты и ответ про email вместо отказа раскрывать инструкции. Повторный запуск на сервере требуется после обновления образа; локальные тесты подменяют API и не подтверждают качество распознавания реальных чеков.

## Третий живой прогон

Лог: 13 запросов к модели, 47 680 входных и 722 выходных токена. Исправления предыдущего прогона подтверждены ответами: публичная навигация без внутренних указаний, последовательный сбор сведений оплаты, сохранение email для команды без раскрытия аккаунта, корректный отказ раскрывать инструкции после смены темы.

В ответе о пополнении без продления оставались две ошибки: HTTPS-ссылки были обёрнуты в `<code>`, а инструкция сайта только предлагалась вместо вывода. Санитайзер теперь снимает формат кода с отдельной HTTPS-ссылки, сохраняя его для токенов и другого текста. Для общего вопроса о пополнении без продления используется актуальная карта: оба канала, если канал неизвестен, либо только указанный пользователем. Вопросы о фактическом списании, статусе и автоплатеже продолжают обрабатываться отдельно; эта инструкция не утверждает, что оплата или продление выполнены. Проверочный скрипт дополнен проверками ссылок и обоих каналов.
